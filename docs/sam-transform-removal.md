# What the SAM port changed

cfn-lint 1.54.0 dropped `aws-sam-translator`. `Transform.transform()` now only
merges `Globals` into resource properties and validates the template against
the SAM schemas; it no longer expands `AWS::Serverless::*` into the resources
CloudFormation deploys them as. Every rule in this package that read a
generated resource therefore stopped applying to SAM templates.

This document accounts for every behaviour difference between the last release
with the transform (cfn-lint 1.53.3) and the port.

Reproduce it with `tools/compare_findings.py`; the invocation is in its
docstring.

## Findings that moved

The check is unchanged, only the resource it is attached to. A finding that
named a resource SAM generated now names the SAM resource itself.

| Rule | Before | After |
|---|---|---|
| ES2000, ES2003, WS2002 | `Resources/ApiprodStage` | `Resources/Api` |
| WS2001 | `Resources/ApiprodStage` | `Resources/Api` |
| WS1000, ES1005, ES1006, WS1004 | `Resources/Function` (the generated `AWS::Lambda::Function` shares the logical id) | unchanged |
| WS1003 | `Resources/FunctionRole` | `Resources/Function` |
| ES1007 | `Resources/FunctionSNSPermission` | `Resources/Function` |
| WS3000 | generated `AWS::AppSync::GraphQLApi` | `Resources/GraphQLApi` |
| WS5000 | generated `AWS::StepFunctions::StateMachine` | `Resources/StateMachine` |

ES1007 also reports once per function now, where it used to report once per
generated permission. A function with two asynchronous events produced two
findings and produces one.

## Findings that moved to an event

There is no resource left to attach these to, so they name the event that used
to generate one.

| Rule | Before | After |
|---|---|---|
| ES1001 | generated `AWS::Lambda::EventSourceMapping` | `Resources/Function/Properties/Events/<name>` |
| ES4000 | generated `AWS::Events::Rule` | `Resources/Function/Properties/Events/<name>` |
| ES7000 | generated `AWS::SNS::Subscription` | `Resources/Function/Properties/Events/<name>` |
| ES2000, ES2003, WS2002 (implicit API) | generated `ServerlessRestApiProdStage` | `Resources/Function/Properties/Events/<name>` |

## Findings replaced by I9306

I9303 required cost allocation tags on the roles, stages, domain names and
deployment groups SAM generated. Those resources are gone from the template, so
the tags are required on the SAM resource itself. SAM only copies them onward
when `PropagateTags: true` is set, which the new I9306 asks for on
`AWS::Serverless::Function` and `AWS::Serverless::StateMachine`.

`AWS::Serverless::Api` and `AWS::Serverless::HttpApi` have `PropagateTags` too,
but they tag their stage either way and the stage is the only taggable resource
they generate, so I9306 leaves them alone.

## Checks that were dropped on purpose

Each of these used to fire on a generated resource and has no SAM property that
would silence it. Reporting them would be a finding nobody can fix.

| Rule | Dropped for | Why |
|---|---|---|
| ES1001 | `SQS`, `DocumentDB`, `SelfManagedKafka` events | the SAM schema has no `DestinationConfig` on them - only `DynamoDB`, `Kinesis` and `MSK` have one |
| ES4000 | `CloudWatchEvent` events | the SAM schema has no `DeadLetterConfig` on them - only `EventBridgeRule` and `Schedule` have one |
| ES6000 | the queue generated by `EventInvokeConfig.DestinationConfig.OnFailure.Type: SQS` | that queue *is* a dead letter queue, and ES6000 already exempts queues used as one |
| W9311 | the same generated queue | SAM offers no way to encrypt it; a template that needs an encrypted failure destination declares its own queue and points `Destination` at it |
| I9303 | generated domain names, event rules, permissions, aliases and versions | SAM does not tag any of them, with or without `PropagateTags` |

`tests/test_sam.py` derives the ES1001 and ES4000 splits from the SAM schema
cfn-lint ships, so they fail rather than drift if SAM ever gains the property.

## One check that fires without a clean fix

ES7000 reports every `SNS` event without a `RedrivePolicy`, and a template that
adds one is answered by cfn-lint with `E3002`.

The cause is upstream in SAM, which describes its SNS event source twice and
disagrees with itself:

| | `RedrivePolicy` |
|---|---|
| `samtranslator/model/eventsources/push.py`, `class SNS` - the runtime model the transform uses | declared, and copied onto the generated `AWS::SNS::Subscription` |
| `samtranslator/internal/schema_source/aws_serverless_function.py`, `SNSEventProperties` - what the published JSON schema is generated from | missing |

cfn-lint vendors the published schema: all 18 `*EventProperties` models in its
bundled `AWS::Serverless::Function` schema match SAM's schema source exactly.
So this is not cfn-lint drift, and it is not new - cfn-lint 1.53.3 ships the
identical schema. What 1.54.0 changed is which of the two descriptions does the
validating. Under the transform a SAM resource was vetted by the runtime model,
which knows the property; now it is vetted against the JSON schema, which does
not, and the omission became reachable.

Fixing it means fixing SAM's schema source; cfn-lint picks that up on its next
schema import, the way it already hand-patches
`EventBridgeRuleEventProperties.State` in
`patches/extensions/all/aws_serverless_function/manual.json`. Until then the
finding-free fix is an explicit `AWS::SNS::Subscription`.

`tests/test_sam.py::test_a_sam_sns_event_still_cannot_carry_a_redrive_policy`
fails once that lands; at that point `sns.py`'s note can go and an
`es7000-sam.pass.yaml` fixture becomes possible.

## Differences that are not ours

These come from cfn-lint's own rules losing the generated resources they used
to inspect, or from checks that caught up with fixtures that were always
slightly wrong:

- `I3011`, `I3013`, `E1156` on generated resources.
- `W2531` on `nodejs20.x`, which reached end of life on 2026-04-30.
- `W1031` on ACM tag values containing parentheses.
- `E1158` on `my-topic-arn`, which is not a topic ARN.
- `W3705` on a `MethodSettings` entry that sets nothing.

## Rules that needed no change

I9304 and I9305 read resource types SAM never generates. ES6000 is covered
above. `AWS::Serverless::Connector`, `Application`, `SimpleTable` and
`LayerVersion` have no rule coverage, and had none before either - the types
they generate are ones no rule inspects.
